Review `2026-11-05-invitation-rollout.sql` in this directory. Its SHA256 with

replacement acceptance. Approval of the initial bundle does not authorize
that subsequent step automatically.

## Reproducible isolated verification

Run `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-invitation-rollout.ps1`.
The script uses a disposable PostgreSQL 17 container with no network and no
published port. The image must already be installed. It removes its container
after the check. Its fixture deliberately has legacy html NOT NULL, lacks
accepted_by and target_id, and reproduces the staging directory return signature.

The integrated check passed on 5 November 2026.

- Platform company creation queued one template-only owner invitation.
- Resend reused the pending invitation.
- Acceptance required a password update and owner legal consent.
- Both agreements were stored for the platform and the owner.
- Acceptance recorded the owner identity. Reuse was denied.
- Expired and revoked invitations were denied.
- The entire initial bundle could be applied again successfully.
- After simulated successful cutover, authenticated direct calls to both old
  RPCs were denied by database execution privileges.

This fixture exercises database transitions. Auth password updates are simulated
in the local auth table. It does not demonstrate provider delivery, a real
Supabase Auth link, browser password setup, or hosted deployment behavior.
