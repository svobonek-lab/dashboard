# Production migration plan: outbox run evidence

**Status: proposal only. No production SQL has been applied or approved.** Source: `supabase/migrations/20261027000000_app_email_outbox_runs.sql`. It creates a service-only run-summary table, a completed-time index, RLS and narrow grants. It does **not** create or repair the underlying `app_email_outbox`, scheduler, email provider or invitation delivery contract.

## Known mismatch and preflight

The approved November 8 snapshot showed `app_email_outbox` present and `app_email_outbox_runs` absent. Recheck both with project-scoped read-only `supabase-ci`, including columns, check constraints, RLS, table/default privileges and existing similarly named tables. After fresh metadata reconciliation, apply the minimal new run-table contract first to disposable PostgreSQL and isolated staging with synthetic runs. Keep scheduler and customer invitation sending disabled until separately reviewed.

## Verification query

Run this metadata-only query through approved read-only `supabase-ci` before and after a separately approved migration. It verifies presence, RLS, grants, columns and the index; it does not prove worker correctness.

```sql
select c.relname as table_name, c.relrowsecurity as rls_enabled,
       c.relforcerowsecurity as force_rls, c.relacl as table_acl,
       pg_catalog.has_table_privilege('anon', c.oid, 'SELECT') as anon_select,
       pg_catalog.has_table_privilege('anon', c.oid, 'INSERT') as anon_insert,
       pg_catalog.has_table_privilege('authenticated', c.oid, 'SELECT') as authenticated_select,
       pg_catalog.has_table_privilege('authenticated', c.oid, 'INSERT') as authenticated_insert,
       pg_catalog.has_table_privilege('service_role', c.oid, 'SELECT') as service_select,
       pg_catalog.has_table_privilege('service_role', c.oid, 'INSERT') as service_insert,
       pg_catalog.has_table_privilege('service_role', c.oid, 'UPDATE') as service_update
from pg_catalog.pg_class c
join pg_catalog.pg_namespace n on n.oid = c.relnamespace
where n.nspname = 'public' and c.relkind in ('r', 'p')
  and c.relname in ('app_email_outbox', 'app_email_outbox_runs')
order by 1;

select a.attname as column_name,
       pg_catalog.format_type(a.atttypid, a.atttypmod) as data_type,
       a.attnotnull as not_null
from pg_catalog.pg_attribute a
where a.attrelid = to_regclass('public.app_email_outbox_runs')
  and a.attnum > 0 and not a.attisdropped
order by a.attnum;

select i.relname as index_name, pg_catalog.pg_get_indexdef(i.oid) as definition
from pg_catalog.pg_index x
join pg_catalog.pg_class i on i.oid = x.indexrelid
where x.indrelid = to_regclass('public.app_email_outbox_runs')
order by 1;
```

Review effective privileges for `anon`, `authenticated` and `service_role`; expect no browser-role access and only the reviewed service-role operations. Test worker retry, duplicate-send protection and failure summaries with synthetic staging data before enabling any scheduler.

## Rollback

Operational rollback comes first: disable the scheduler/worker through a **separately approved** configuration change and verify it has stopped before touching the table. Preserve run summaries as incident evidence; a schema rollback is not automatically required. If removal is explicitly approved later, export/retain the bounded operational summaries through an approved process, verify no worker references the table, then drop the new index and table in a reviewed transaction. Never delete or alter `app_email_outbox` or delivery history as part of this rollback. Confirm absence and grants with the query above. An in-progress `running` row does not prove that no email was sent; reconcile delivery state before retry.

## Approval gate

Provide fresh outbox/run-table metadata, worker compatibility findings, exact candidate SQL/hash, disposable and isolated-staging evidence, retention and rollback decision, and separate written approval for each production SQL or scheduler/configuration write. This plan authorizes none.
